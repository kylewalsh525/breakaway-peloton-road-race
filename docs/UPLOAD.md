# Upload this project to GitHub

Unzip into a new folder. The project is self-contained and has no connection to any other repository. A new **private** repository is a reasonable starting point for an unverified hardware pilot.

Create an empty GitHub repository without adding a separate README/license/gitignore. Replace `YOUR-ACCOUNT` and `YOUR-REPOSITORY` below with your GitHub account or organization and repository name. From the unzipped project folder:

```sh
git init -b main
git add .
git status --short
# Review staged filenames before committing. Never stage .env or a signing key.
git commit -m "Initial Breakaway arcade racer implementation"
git remote add origin https://github.com/YOUR-ACCOUNT/YOUR-REPOSITORY.git
git push -u origin main
```

Authenticate using your existing GitHub credential manager or SSH setup. Never put a token directly in a command, README, environment example or chat. Replace the remote if you chose another repository name. No connector token is included in the ZIP, and no GitHub repository was changed by producing it.

The source, documentation, screenshots and executed reports are useful to retain. Generated Android game assets and `dist/` are ignored and regenerated by `npm run build`. The ZIP additionally includes `PLAY-SOLO.html` so the game can be opened before setting up a development environment. `MANIFEST.sha256` describes the delivered ZIP contents; it is not a permanent checksum of files after you edit the project.

After push, review both workflow results. The Android workflow's first successful build is required before trying the APK; its existence in this repository is not evidence that it has already passed. Artifact downloads appear on each GitHub Actions run. Do not advertise physical compatibility until the separate hardware checklist is completed.
